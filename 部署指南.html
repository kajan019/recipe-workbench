菜谱工作台 · 部署与同步说明书

这篇只讲一件事：怎么把你这个菜谱应用放到网上，变成一个永久网址，并且手机和电脑数据互通、不会丢。全程不用打字命令，只在网页上点鼠标。

你只需要：一个 GitHub 账号（你已有），和一个浏览器。电脑、手机都用同一个浏览器登录这个 GitHub 账号即可。

第一部分：把应用放到网上（拿永久链接）

在电脑上用浏览器做，只做一次。

1打开 github.com，登录你的账号。
2右上角点 “+”（加号）→ 选 “New repository”（新建仓库）。
3在 “Repository name”（仓库名字）里填：recipe-workbench
下面选 “Private”（私有，只有你能看，推荐）；想给别人看就选 “Public”。
其它都不用动，拉到最下面点 “Create repository”（创建仓库）。
4创建好后，页面上会有一行蓝字 “…or upload an existing file”（或 “uploading an existing file”），点它。
5把下面 3 个文件拖进虚线框（或点 “choose your files” 选）：
  • index.html
  • app.js
  • styles.css
如果还能看到一个叫 .nojekyll 的文件，也一起拖进去；看不到就不传。
注意：不要传 server.js 这个文件。
6拖完后，页面底部点 “Commit changes”（提交）。
7在这个仓库页面，点右上角 “Settings”（设置）。
8左边菜单点 “Pages”。
9在 “Build and deployment” 下面：
  • Source（来源）选 “Deploy from a branch”（从分支部署）
  • Branch（分支）选 “main”，右边文件夹选 “/ (root)”，点 “Save”（保存）。
10等 1~2 分钟。回到 “Pages” 页面，上面会出现一个网址，类似：
https://你的用户名.github.io/recipe-workbench/
这就是你的永久链接！ 建议收藏（加书签）。

第二部分：让数据自动保存 + 手机电脑通用

每台设备（电脑、手机）第一次用时做一遍。

11还是在 GitHub，点右上角你的头像 → “Settings”（设置）。
12左边最下面点 “Developer settings”（开发者设置）。
13点 “Personal access tokens” → “Fine-grained tokens”（精细令牌）。
14点 “Generate new token”（生成新令牌）。
15填写：
  • Token name：填 recipe-sync（随便填也行）
  • Repository access：选 “Only select repositories”，在下拉里选 recipe-workbench
  • 往下找 Permissions → Repository permissions → Contents：右边选 “Read and write”（读写）
  • 拉到最下面点 “Generate token”。
16生成后会出现一串字母（以 github_pat_ 开头）。
立刻复制保存好！这串字母只显示这一次，关掉就再也看不到了。
17用浏览器打开你的永久链接（第 10 步那个网址）。
18页面右上角点 “☁ 同步” 按钮。
19在弹窗里填：
  • 令牌：粘贴第 16 步复制的那串
  • 仓库：填 你的用户名/recipe-workbench（中间是斜杠 /）
  • 分支：main（默认就是）
  • 文件路径：data.json（默认就是）
  • 勾选 “自动同步”
20点 “测试连接”——如果显示绿色“连接成功”，再点 “保存设置”。

完成！以后怎么用

• 在电脑上添加/修改菜谱，关掉网页也没事，数据已自动存到网上。
• 手机上用浏览器打开那个永久链接，点 “☁ 同步” 填同样的令牌和仓库，数据就和电脑一模一样了。
• 换手机/清了浏览器？重新点 “☁ 同步” 填一次即可。

常见问题

测试连接失败？ 检查：① 仓库名是否写成 “用户名/recipe-workbench”；② 令牌是否复制完整（从头到尾）；③ 令牌权限是否是“读写”。

网页打不开？ GitHub Pages 第一次要等 1~2 分钟，稍后再试。

令牌安全吗？ 令牌只存在你自己的浏览器里，只对这个仓库有效，很安全。如果担心，随时去 “Fine-grained tokens” 里把它删掉重做一个。

第三部分：以后怎么更新功能 / 改代码

先放心：代码不会自己变。 GitHub Pages 只在你把新文件传上去时才更新，平时永远是上传的那个版本。

A最省事（推荐）：你来说，我来改，你再传一次。
① 用大白话告诉帮你做应用的人想要什么新功能/改动；
② 对方在这个工作台改好、测好，把更新后的 index.html / app.js / styles.css 给你；
③ 你回到 GitHub 那个仓库，像第 5 步那样把新文件拖进去覆盖旧的（或点进旧文件 → 右上角铅笔图标 → 粘贴新内容 → 提交）；
④ 等 1~2 分钟，刷新永久链接即可看到新功能。
B更省事：连上 GitHub，让对方直接帮你传。 在 WorkBuddy 左侧连 GitHub 并授权后，对方改完可直接推送到网上，你连拖文件都不用。
两个放心：
• 菜谱数据不会丢：数据存在通过令牌同步的 data.json，更新代码文件碰不到它。
• 改坏了也不怕：GitHub 每次改动都有记录，可随时退回旧版本。
